# 完整版本与第三方云备份

阶段 5 在未登录的本地空间提供完整版本及第三方备份。账号用于多设备条目同步，按[独立批次](desktop-rebuild/ACCOUNT_SYNC_FOUNDATION_2026-10-27.md)接入；本轮不接入官方完整备份和旧官方快照导入，其公开调用继续返回 `STAGE_NOT_READY`。

在“设置 → 数据备份”设置独立备份密码（至少 6 位），再创建完整版本。版本仍为 `.eizhubackup` v1，使用现有 Argon2id / AES-GCM codec；按加密前规范化业务 payload 的 SHA-256 去重。密码轮换影响之后生成的版本，旧版本使用原密码恢复；业务内容未变时保留已有版本及原密码，不重复加密。

版本只包含分组、凭据、服务器和片段。UI 设置、历史、传输、隧道、备份目标和 OAuth 凭据不进入交换文件。版本文件、密码、目标配置和令牌在数据库 Worker 内按用途加密。普通目标列表仅返回名称、类型、启用状态和授权标记。

可以手动创建、变更防抖后创建、按小时间隔或系统时区的每日时间创建；启用变更自动备份时，正常退出也等待本地快照。可单独打开自动提交。应用不运行时不会执行调度，恢复运行后补做一次，不逐次补齐错过的时刻。关闭先经过现有未保存编辑器确认；备份忙或最终快照失败会保留窗口并提示，不承诺强制终止、系统断电时创建退出快照。

本地默认保留 20 个版本，0 表示不按数量清理，硬上限 1000 个。超过保留数的版本只有在已提交到所有当前启用目标时才自动移除；未提交的版本保留。删除操作明确确认只删除本地副本。云端默认永久保留。目前只开放 `prompt` 冲突策略及 `keep_forever` 云保留策略，其余历史枚举值返回 `UNSUPPORTED_POLICY`，不会假装完成自动冲突覆盖或云端镜像删除。

## 目标

- WebDAV：填写现有父目录 HTTP(S) 地址、用户名及密码，客户端在其下创建本设备独立目录。使用 Basic 认证；在公网应使用 HTTPS。重定向不自动跟随，避免凭据转发。
- S3 兼容存储：填写存储桶、区域、Access Key、Secret Key；可选 endpoint、prefix、path style。请求以 AWS Signature v4 签名。对象位于 `prefix/spaces/offline-设备ID/`。
- Google Drive：使用 Google Cloud Console 的**桌面应用** OAuth 凭据；授权范围为 `drive.file`，只操作应用创建的独立设备目录。通过系统浏览器授权。
- OneDrive：在 Azure 注册原生桌面应用，按 Microsoft 的回环地址规则，在应用清单登记 `http://127.0.0.1/oauth/onedrive`；运行时使用临时端口。范围为 `Files.ReadWrite offline_access`。使用独立设备目录。

OAuth 使用 PKCE S256、随机 state、5 分钟有效期和一次性回调；监听仅绑定 `127.0.0.1` 的临时端口。固定路径由 state 和 Host 检查保护。目标变化、取消、超时或运行实例结束会关闭监听；不提供本地业务 HTTP 网关。刷新令牌在业务层按目标串行化，更新前检查目标修订。

网络由 Electron 主进程 `net.fetch` 执行，沿用系统代理和 TLS 验证，核心包不导入 Electron。每个请求限制 20 秒及最多 52 MiB 响应；备份文件维持 50 MiB 上限；最多三个目标并行。网络、代理、认证和服务端限流失败保留本地版本，由用户检查目标后手动重新提交，不自动重放结果未知的写操作。

对象名保留 `v000001-摘要前12位.eizhubackup`，索引保留 `eizhu-sync-index` v1 的字段。新安装拥有新设备命名空间，不寻找旧用户目录或旧命名空间。本轮不宣称自动发现其他设备的备份；交换其他设备数据仍可导入其备份文件。

## 确认与恢复

每个目标依次读取有效索引、上传对象、读回核对完整文件摘要、校验索引未变、条件写索引，再次读回确认，最后在数据库中记录该版本的目标确认。已有索引缺少 ETag 时拒绝不安全覆盖。目标在上传期间被编辑或禁用、同版本不同摘要、目录损坏、ETag 冲突均不能记为成功。单个目标失败不撤销其他目标的确认；已成功的目标不会重复上传同一版本。对象上传成功而索引未确认时可能保留未引用对象，禁止据此自动删除云端数据。

Google Drive 的首次同名文件创建不提供名称唯一约束；客户端隔离设备命名空间、检测重复文件并拒绝继续，不承诺跨外部写入者的全局事务。真实云厂商条件写行为仍须使用测试账号验收。

从本地版本或已校验的云目录选择“恢复预览”，输入该版本密码；界面显示来源、摘要统计以及合并/替换差异，确认前不写入业务实体。确认时复核本地修订，变更后必须重新预览；应用前保留加密安全快照，沿用阶段 2 的事务恢复。解密正文不经过渲染进程。

协议依据：[AWS SigV4](https://docs.aws.amazon.com/AmazonS3/latest/API/sig-v4-header-based-auth.html)、[S3 条件写](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)、[Google 桌面 OAuth](https://developers.google.com/identity/protocols/oauth2/native-app)、[Microsoft 回环回调规则](https://learn.microsoft.com/en-us/entra/identity-platform/reply-url)。具体实测范围见阶段 5 报告。
