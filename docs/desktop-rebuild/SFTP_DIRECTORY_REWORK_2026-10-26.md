# 文件夹传输链路优化

日期：2026-10-26。范围：双栏复制、本机目录拖入、目录压缩传输、下载暂存、系统拖出准备，以及队列、冲突和恢复。

## 问题与变更

| 问题 | 本次处理 |
| --- | --- |
| 目录扫描、目标检查发生在创建任务前，长操作占着一次 RPC，用户看不到任务也无法取消扫描 | 当前界面通过 `background: true` 立即取得持久任务；扫描、冲突检查及归档在有界调度器内执行。下载与系统拖出也先创建任务再扫描 |
| 后端返回 `tasks`，前端却必须看到 `task_id` 才接收任务 | 按实际任务列表接收整批任务；后端同时补齐兼容任务 ID |
| 每批独立轮询、仅跟踪首个任务，十分钟后停止 | 当前空间共用一个不重叠的轮询；所有进行中任务持续跟踪，释放页面或切换空间后停止 |
| READDIR 后又对每个文件重新读取元数据、重复检查已知不存在的目标子树 | 递归扫描复用列表的属性；已确认不存在的目标目录下不再逐项预查。执行阶段仍重新检查源、目标和符号链接 |
| 每个进度或步骤变化都加密持久化整个目录清单 | 完整计划与当前游标分别存放，进度仅保存任务状态、当前偏移、摘要和索引；步骤提示单独节流发布 |
| 队列只有字节百分比，空目录和扫描看似停在 0% | 增加扫描、打包阶段、已扫描/已提交项目数量和当前文件；未知总量不展示确定百分比 |
| 冲突处理依赖原 RPC 返回，覆盖文案还误称会删除目标目录 | 冲突持久留在原任务上，支持查询及选择覆盖/重命名/跳过；普通复制合并目录并保留其他内容。类型冲突拒绝覆盖，归档按输出文件类型判断 |
| 目录重新开始会把已提交文件也重新处理，可能因本任务自己的写入再次失败 | 仅重新读取和重传未完成部分，保留已提交内容及其后续外部修改 |
| 默认目录模式与界面默认行为不一致，下载图标依赖面板方向 | 统一默认保留目录结构；方向由实际端点确定；直接复制到本机的任务不再出现“另存下载暂存”的按钮 |

## 持久化与安全

完整计划继续保存在加密 `transfer:<id>` 记录中，增量状态使用独立加密 `transfer-progress:<id>` 记录，写入只进入数据库 Worker 的同步 SQLite 事务。更新完整计划时在同一事务删除旧进度，清除任务时同时删除两条记录。不改变业务 schema 版本，旧完整检查点仍可恢复。

扫描取消会等待当前有界文件系统/协议请求结束，并在继续枚举或写入前检查取消信号。扫描失败或发生冲突之前不会创建目标目录。中途取消不会回滚已经提交的文件。

每个文件仍使用独占暂存文件、写入确认、关闭确认、源/目标变化检查和最后重命名。检查点仍只推进已经确认的字节；本地写入继续在持久检查点前同步。没有通过取消同步、跳过校验或自动覆盖结果未知的写操作换取速度。
