# 对外端口映射与二次提醒（2026-11-04）

最新表单字号、地址选择及右侧动画的实现与本轮验证见 [表单与流向预览报告](PORT_MAPPING_VISUAL_2026-11-04.md)。下文安装包和截图保留当时版本的实际证据。

## 行为

- 默认继续使用回环地址；本地、远端和动态代理均可选择 `0.0.0.0` / `::`，请求在全部 IPv4 / IPv6 地址监听。列表标记“对外监听”。
- 表单选择对外地址时先提示局域网/公网暴露风险；每次手动启动再弹出独立确认，展示名称、SSH 服务器地址、监听位置/端口和目标。取消不建连或占用端口，保存配置也不启动。
- SOCKS5 没有客户端认证，表单和启动确认均明确说明对外开放可能成为任何人可用的代理。
- 确认只授权本次运行，不持久保存，不提供“不再提醒”。停止后再次启动、应用重启和切换空间后都要重新确认；同一已确认运行的断线重连使用原规则。
- 全地址监听不等于公网链路已经打通；客户端使用设备实际 IP/域名连接，`0.0.0.0` / `::` 是监听地址。应用不修改路由器、NAT、防火墙或 SSH 服务端配置。

## 接口与门禁

`tunnel.start` 增加可选输入 `confirmedConfig: TunnelConfig`。回环映射仍可只传 `id`；对外映射必须携带用户确认的配置快照，后端读取当前空间保存的规则并逐项比较名称、服务器 ID、模式、监听、目标及规则 ID。

- 缺少确认：`TUNNEL_PUBLIC_CONFIRM_REQUIRED`，在创建 SSH 连接或监听前拒绝。
- 配置变化：`TUNNEL_CONFIG_CHANGED`，在启动前拒绝；前端重读规则列表并显示错误，不自动重试启动。
- 未增加数据库字段或迁移，确认快照不进入配置、同步或备份。仍复用现有主机指纹、认证、独立 SSH 路由、连接上限和资源释放流程。

远端监听受服务端策略控制。建议使用 `GatewayPorts clientspecified`，使服务器按用户选择的地址绑定；默认 `no` 限制到回环，`yes` 强制通配监听。不能仅凭远端接受监听请求就宣称公网可达。参见 [OpenSSH 官方手册](https://man.openbsd.org/sshd_config#GatewayPorts)。

## 映射方向与草稿修正

原表单切换类型时共用监听和目标地址草稿，且字段名称过于泛化，容易把两端混淆。现将三种模式的地址/端口草稿分开，切回可恢复各自输入；仅保存当前选中的模式。类型与 SSH 服务器选择采用并排布局，缩短表单首层风险提示，让监听端与目标端更容易同时看到；启动时的完整二次确认保留。

| 映射类型 | 监听端 | 目标主机 |
|---|---|---|
| 本地映射 | 本机监听地址/端口 | 远端目标，由 SSH 服务器访问 |
| 远端映射 | 服务器监听地址/端口 | 本机侧目标，由当前电脑访问 |
| 动态代理 | 本机 SOCKS5 监听 | 每次由代理客户端指定，无固定目标字段 |

三个模式的监听地址都可选择 `0.0.0.0` / `::`；远端映射的选择位于“服务器监听地址”。目标主机填写具体 IP 或域名。两种固定映射默认目标都可为 `127.0.0.1`，但分别指向 SSH 服务器自身和当前电脑，表单已明确说明。

补充验证：页面/API 17 项通过，类型、lint、固定基线校验及桌面构建通过。真实 Electron 构建输出完整烟测通过：实际切换本地→远端→本地→动态→远端，验证独立草稿、服务器监听选择 0.0.0.0、保存结果、二次确认及远端 TCP 回显。本轮只调整渲染端表单和验收代码，未修改转发引擎、数据库或 IPC 契约；前次安装包证据保留。
