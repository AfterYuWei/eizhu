## 验收入口与边界

新增 `desktop:accept:sync`，启动独立 Electron 主入口和两个 RuntimeHost。每端使用独立临时数据根、设备密钥、全局库、账号业务库、utilityProcess、数据库 Worker 和计算 Worker，不打开日常应用目录。

- `--synthetic` 使用本机 HTTP/SSE 协议模拟器，不访问线上账号服务。
- `--live` 只访问固定 `https://eizhu.yuweinfo.com/`，不提供任意后端地址；沿用 main 的路径/方法校验、有限响应和 SSE 背压。
- 验收入口不增加 renderer/preload 业务方法。日常 UI 已在第三批通过 Web 与最终安装包验证，本工具直接驱动主进程与真实业务进程，不能单独替代 UI 验收。
- 设备密钥使用新目录的受限文件模式；真实系统密钥库仍待验。没有管理员初始化、后台配置或旧数据清理操作。
- 登录密码、同步密码和轮换后密码仅在可信验收进程内随机生成，不输出、不写源码或明文文件。验证码通过不回显的标准输入提交；报告只含步骤、版本、计数和请求密文摘要。
- 专用账号会执行密码重置并结束于随机密码状态。测试条目成功后删除，云端保留协议墓碑、账号和设备登记；不会删除账号。客户端加密目录保留供问题定位，不将目录加入源码。

## 运行方法

先构建，再验证工具本身：

```bash
npm run desktop:build
npm run desktop:accept:sync -- --synthetic
```

真实验收在提供专用邮箱后执行。将邮箱地址写入本机受限的小型文本文件，不需要提供邮箱密码或现有账号密码：

```bash
npm run desktop:accept:sync -- --live --email-file=/绝对路径/专用测试邮箱.txt
```

收到 `input_required` 时输入一行 JSON：`{"code":"邮件中的六位验证码"}`；需要重发时输入 `{"action":"resend"}`。工具分别等待验证和找回邮件，不会把合成验证码用于真实模式。错误验证码可重新输入，限流时保留等待。注册发现邮箱已存在则停止，不能使用未知的已有账号做密码重置。

成功后，脱敏报告写入 `artifacts/acceptance/{synthetic|live}-<platform>-<arch>.json`，临时目录路径打印在输出中。失败保留隔离目录，不自动重放未知的认证写入；同步恢复遵循冻结请求协议。

## 用例与证据

两个客户端使用同一专用账号，覆盖：

1. 注册、邮箱验证、注入一次过期响应后执行服务端刷新，并确认旧 refresh token 被拒绝。
2. 创建/解锁包装密钥、首次预览、确认后合并原离线条目、第二目录固定水位快照。
3. 分组、凭据、服务器和片段的加密往返，凭据/分组引用保持有效；SSE 唤醒另一端增量拉取。合成服务器使用 `.invalid` 地址，不建立 SSH 连接，不执行片段。
4. 两端暂停期间并发编辑，旧冲突修订被拒绝，保留本地后两端收敛。
5. 服务端返回提交成功后由客户端丢弃响应，重启通过 requestId 查询恢复，客户端没有第二次提交。
6. 整体替换进入下一 epoch，另一端重取快照并保留本地未上传修改。
7. 轮换同步密码；退出回到该端原离线空间，旧 refresh token 被拒绝；重新登录后旧同步密码无法解锁、新密码可解锁。
8. 刷新成功响应被客户端丢弃后要求重新登录，账号空间、本地条目和记住解锁保留。
9. 找回邮件和登录密码重置使另一端会话失效；重新登录、重启后仍可使用本机缓存 DEK。
10. 删除本次创建的测试条目，确认另一端收敛，关闭两端自动同步。
