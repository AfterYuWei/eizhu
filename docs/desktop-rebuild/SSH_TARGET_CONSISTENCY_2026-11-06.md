# SSH 目标与同步配置一致性（2026-11-06）

## 用户现象与排查边界

用户反馈：正式账号空间中编辑并保存服务器 A，从侧栏连接时配置与连接状态显示 A 的 IP，实际进入 B；未启用 SSH 跳板。重启 admin 后端并手动同步成功后恢复。此次未读取生产账号数据、未请求生产同步接口，也未在用户真实服务器上复现故障，不能把以下客户端缺口直接认定为本次生产故障的唯一根因。

左下角“云端”表示账号工作空间，服务器配置仍由本机数据库 Worker 持有，SSH 由本机业务进程发起。同步后端不可用时，本地保存及 SSH 应继续正常工作；新修改必须保留为待同步，不能依赖先恢复后端才能用于 SSH。

## 已修补的客户端缺口

- 保存服务器后立即应用数据库提交响应；列表读取按请求顺序与工作空间代次接收，迟到的旧列表不能把新配置替换回去。
- SSH 创建请求携带列表中选择的主机与端口。本次连接只解析一份数据库连接计划，实际目标不一致时返回 `PROFILE_CHANGED`，在任何 TCP/代理/跳板拨号前停止。
- 已有会话的手动及自动重连继续核对原目标；地址或端口发生变化时，需要从刷新后的服务器列表重新打开连接，不静默改变旧会话的目标。用户名与凭据仍读取最新配置，包括 Vault 实际解析的用户名。
- 连接状态及就绪元数据包含实际计划中的服务器标识、名称、主机、端口和用户名。终端按会话及服务器归属更新 Tab、地址提示与连接弹窗，拒绝其他会话/服务器的就绪消息。`PROFILE_CHANGED` 自动刷新列表。

该保护解决列表与数据库配置错位导致的误连接，并不判断目标 IP 之后的 NAT、SSH 服务端转发或远端主机身份；原有主机指纹验证继续执行。
