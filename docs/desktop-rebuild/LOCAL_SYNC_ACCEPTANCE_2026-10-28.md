## 入口与环境边界

独立验收工具增加固定 `--local` 模式。该模式的有限请求与 SSE 都映射到 `127.0.0.1:8080`，没有任意服务器地址输入；桌面产品的正式服务地址保持固定。每次仍创建两个新隔离客户端目录，不打开日常应用数据。

```bash
npm run desktop:build
npm run desktop:accept:sync -- --local --email-file=/绝对路径/测试邮箱.txt
```

`--synthetic`、`--local`、`--live` 必须三选一；`--live` 明确表示生产，本轮不使用。结果分别写入 `artifacts/acceptance/{synthetic|local|live}-<platform>-<arch>.json`；成功与失败报告都带有实际目标和模式，本机模式标记 `productionBackend:false`。

续跑只允许恢复相同环境的已停止测试目录；生产测试目录不能传给本机模式。原有身份、预览确认和冻结请求规则继续执行，不自动导入日常离线数据或重放未知写入。

对用户明确允许重置的已有本机测试账号，使用 `--local --reset-existing-account --email-file=...`。工具通过真实找回邮件设置随机登录密码，不重复注册；此选项在生产模式启动前拒绝执行。测试密码和验证码不写入源码、明文文件或报告。

该选项只恢复登录，不覆盖已有的同步包装密钥。本轮账号尚未设置同步密钥，因而可初始化本轮随机同步密码；已有包装密钥而没有解锁缓存的新目录仍会按正常规则拒绝错误同步密码，不提供绕过解密的重跑入口。保留的加密客户端目录用于本轮补充检查。

- 请求发送前丢失，重启先查询原 requestId；404 后重发的请求体和密文 SHA-256 完全相同。
