# SSH 连接弹窗与诊断信息优化（2026-10-29）

## 问题与变更

- 原弹窗的固定七步与实际 `resolve`、`proxy`、`host_key`、`ssh_auth` 等阶段不一致；失败统一改成 `failed` 后，界面会错误定位到第一步。现按后端真实操作展示当前阶段，失败快照保留最后实际执行的阶段，不推断已完成步骤。
- 弹窗采用 600px 紧凑布局，沿用共享表面、中性色、字号和减少动态效果设置。主机指纹、失败详情分别展示，避免多处重复同一报错。
- 识别 DNS、端口拒绝、网络不可达、超时、连接重置、认证、加密算法协商、主机指纹、代理与终端分配等错误。保留稳定错误码，界面提供对应建议；未知原因明确说明，禁止将库异常原文或凭据输出到记录。
- 主机密钥核对阶段仅在实际收到主机密钥时发送；登录认证后实际请求交互式终端时发送 `starting_shell`。
- 连接记录默认折叠，展示操作、时间与安全消息，支持复制诊断信息。连接耗时不因阶段或弹窗状态切换而归零；自动重连启动后进入真实操作状态，新一轮记录独立计时。
- 失败快照单独回放时也能显示错误，无需依赖第二条错误事件；指纹确认失败不会再次渲染为待确认状态。

## 取消连接行为

- “取消连接”调用既有会话关闭接口，实际终止 SSH 握手、认证等待和自动重连计时器，保留标签与服务器引用，并提供手动连接入口。仅取消连接不会移除标签或改变当前标签焦点。
- 创建或重连请求在取消后才返回时，释放迟到的会话；取消后的旧事件不再重新打开弹窗或恢复连接状态。关闭失败保留会话 ID，在连接日志中显示原因并允许再次取消。
- Web 全部 75 个测试文件 / 317 项测试、Web 构建（含类型检查）、相关 ESLint、固定兼容校验与差异检查通过。新增覆盖取消后保留标签、清除重连信息、释放迟到响应、忽略旧事件、再次手动连接，以及取消失败后重试。
- 此次使用既有桌面会话接口，没有修改 IPC 或 SSH 业务进程；未重新运行安装产物烟测或连接实际服务器。
