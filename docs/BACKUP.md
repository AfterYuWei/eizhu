# 备份与恢复契约

阶段 2 已提供生产文件导入/导出、完整恢复及加密安全快照；云目标、自动调度和完整版本管理在阶段 5 实现。
固定旧实现样本及独立 Node 字节校验已保留，见 [精确格式与来源](desktop-rebuild/COMPATIBILITY.md)。

继续导出 `.eizhubackup` v1，接受 `.eizhubackup` 与 `.xcbackup`，保留 none/plain/encrypted、Argon2id 参数、UTF-8 密码、AES-256-GCM、AAD、Base64 与 nonce/ciphertext/tag 顺序。
分组、服务器、凭据、片段保持 ID、排序和关联；重新生成 ID 同步修正父组、分组、凭据与跳板关联。默认 skip，也支持 overwrite/regenerate。文件正文仅在 Node/Worker 间传递，选择器返回绑定窗口和运行上下文的授权引用；读取上限 50 MiB，文件在选择后被替换或修改时须重新选择。
预览加密隔离保存，15 分钟过期且最多保留 4 份；导入重新核对文件摘要与本地修订。完整恢复支持 merge/replace，确认界面只展示来源与变化计数。每次应用都在同一事务中保存设备密钥保护的安全快照、更新业务/审计/outbox并消费预览；失败全部回滚。取消预览不改业务数据，覆盖前快照可以再次预览恢复。
导出通过系统保存对话框，先写同目录临时文件再替换目标，取消不生成文件。安全快照当前不自动清理；自动版本保留策略属于阶段 5。
不读取旧数据库、key、设置或任务来获得兼容性。旧备份不包含 UI 设置、历史、未完成传输和云目标配置，不能承诺恢复这些内容。

验收必须使用冻结旧样本，覆盖中文密码、代理密码、受口令保护的真实 OpenSSH 私钥、依赖重映射、错误密码/损坏文件/限制及回滚。
XControl 三模式构造样本经旧读取器验证；另有原历史空样本。不能把构造样本标为来自历史用户设备，也不能只以新实现自导出/自导入证明兼容。
