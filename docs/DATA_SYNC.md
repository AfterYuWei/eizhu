# 本地操作、账号实时同步与独立备份

SQLite 是当前空间直接读写的数据源。增删改先提交本地事务并返回成功，同一事务内保存设备密钥加密的待提交内容；提交后立即唤醒账号同步任务。网络请求不阻塞页面，云端失败不回滚本地数据。

## 空间和模块

- `account` 负责认证、稳定用户 ID 和带账号校验的 HTTP 请求。登录元数据在 `application.db`，使用原设备密钥保护。
- `app/workspace.rs` 装配每个空间的领域服务，取消并等待后台任务、关闭 SSH/SFTP，并发布带代次的空间切换事件。
- `sync` 只负责账号条目同步、密钥、待提交队列、拉取游标和冲突。
- `backup` 负责完整快照、恢复、安全快照；`backup/archive` 负责版本、第三方目标、OAuth、官方对象备份和独立调度器。

原 `eizhu.db`、`key` 和归档作为本地空间保留。账号数据库和密钥位于 `spaces/<SHA256(服务器身份:稳定用户ID)>/`，备份也在对应空间中。账号过期仍可离线使用该空间；显式退出返回本地空间。空间切换不转移待提交队列。移动端主密钥使用对应空间的 Keystore/Keychain 命名空间，原默认命名空间继续兼容。

前端请求、同步事件和 SFTP 事件携带 `workspaceGeneration`；切换后旧请求结果被丢弃，业务 Store 清空，布局重建。后端任务只持有所属空间的服务与数据库，不通过活动空间重新寻找数据。

## 本地可靠队列

`infrastructure/database/sync_migration.rs` 增量创建 `realtime_state/items/outbox/requests/conflicts`。SQLite 触发器捕获服务器、分组、凭据和片段的真实写入，业务写入和队列写入一起提交或回滚。凭据关联更新、批量写入和导入保留事务批次；删除也保留加密记录。主机指纹和本地使用时间不参与同步。

请求在网络发送前固定请求 ID、队列记录 ID、目标修订号和密文。确认只删除该请求的队列记录，上传期间产生的新修改继续排队。结果未知时先查询原请求，不能重新生成相同操作。进程重启会扫描未确认队列；一秒扫描也负责补偿丢失的唤醒通知。

可重试错误使用带抖动的指数退避，最多 60 秒。认证、配额或协议错误等待重新登录、网络恢复或手动重试。首次接入、密码解锁和冲突解决也会重新唤醒任务。SQLite 和加密工作由阻塞线程执行；关闭同步任务时等待已开始的阻塞工作退出。

## 加密协议和云端一致性

客户端检查 `/api/sync/v2/capabilities`，注册设备，通过 `/keys` 读取或 CAS 更新包装数据密钥。每个账号使用随机 256 位数据密钥；独立同步密码经 Argon2id 派生包装密钥。修改同步密码只重包数据密钥。业务内容和关联关系在客户端使用 AES-256-GCM 加密，AAD 绑定协议、用户、条目类型/ID、目标修订号、数据代次、密钥版本和删除状态。

服务端 PostgreSQL 按 `(user_id,item_type,item_id)` 存储修订号、变更序号、数据代次、本地代次、密钥版本、删除状态和 `BYTEA` 密文。服务端不能读取业务字段或同步密码。

- `POST /push` 在账号锁和同一数据库事务内校验批次、CAS 修订号、水位与配额，保存条目、变更批次和幂等请求结果。
- `GET /requests/{requestId}` 查询未知结果；相同 ID、不同内容被拒绝。
- `GET /changes` 按固定水位分页返回完整事务批次。
- `POST /snapshots` 和快照分页接口提供固定水位的物化全量快照，保留 15 分钟。
- `GET /events` 提供 SSE；事务内 PostgreSQL NOTIFY 在提交后到达各服务实例的 LISTEN 连接。

SSE 只发送变更序号和心跳，不发送明文或凭据。15 秒心跳维护连接；设备接到通知立即拉取。断线重新核对游标；60 秒补查用于漏通知恢复，与本地修改的立即上传无关。变更日志保留 30 天，删除标记和幂等请求结果持续保留。游标过期或整体替换导致代次变化时，通过全量快照重新核对本地队列。

## 首次接入、差异和冲突

首次接入先预览本地/云端数量，可合并、使用本地或使用云端。提交前再次校验本地代次和云端水位。SQLite 中的准备、队列固定及初始化状态更新属于同一事务；本地覆盖云端使用新的数据代次，其他设备重新核对。覆盖前保存设备密钥保护的安全快照。

无本地修改的条目直接应用云端变化；等价业务内容合并确认；不同条目可以并行收敛。同条目不同内容、编辑与删除相遇、缺失引用或循环关系保存为冲突，远端版本持久化后再推进游标。冲突阻塞所属事务批次及引用该条目的批次，无关批次继续处理。

冲突页面展示双方业务摘要，凭据内容不进入摘要。选择保留本地时基于最新远端修订号重新提交；使用云端时通过本地事务撤销该条目的待提交记录并应用远端内容。选择携带看到的远端修订号；解决期间远端再次变化会要求重新选择。

全局和条目分别显示本地已保存/待同步、同步中、已同步、离线、失败、冲突或待接入/待解锁。删除记录在同步列表中仍可追踪。本地成功提示与云端确认独立。

## 完整版本和第三方云

第三方 WebDAV、S3、Google Drive、OneDrive 只属于数据备份。未登录账号时仍可使用，后台从不读取第三方业务数据并自动合并。

每个空间、设备各自递增版本号，远端目录包含空间和设备命名空间。每次提交前生成当前完整快照；内容和备份密码代次未变化时复用最新版本。只提交最新版本，不补传旧版本。上传期间版本文件固定，各目标的确认原子保存；失败目标从持久化确认记录恢复，调度器每 30 秒独立重试。

默认云端永久保留、本地保留 20 个版本。已被更新版本替代的未上传旧版本也受本地保留策略约束。兼容的 `mirror_local` 策略将云端删除任务持久化，失败后继续重试。停止调度器取消网络任务并等待已开始的快照工作退出；进程退出时也等待退出快照完成。修改目标时与上传互斥，并重新提交该目标的最新版本，避免沿用旧配置的确认。

备份密码与同步密码独立。迁移复制原同步密码作为初始备份密码，此后独立修改；密码轮换生成新的加密版本，旧版本可输入原密码恢复。`.eizhubackup` 与 XControl 导入继续兼容。

官方完整备份使用 `/api/backup/v1`，由账号认证访问服务器配置的 S3 兼容存储。PostgreSQL 只保存目录、状态、索引、配额和上传租约。对象上传并校验后才能恢复；删除任务等待正在进行的上传退出，清理失败保留任务，重复清理不会重复扣减配额。对象存储故障不影响条目同步。

用户主动恢复先在隔离临时数据库中校验完整数据和引用，生成设备加密的预览记录。取消只查看，不修改当前空间。合并或替换前再次核对本地代次，同一事务保存安全快照和业务变更，产生普通队列记录并立即唤醒账号同步。

## 兼容和部署

旧备份配置、个人目标、OAuth、版本和日志采用可重入迁移复制到 `backup_*` 表，原库、密钥、旧表和归档不删除。旧备份类 `sync_*` 命令集中在 `commands/backup_compat.rs` 保留一个过渡版本；账号条目同步使用新的 `sync_*` 契约。OAuth 完成事件为 `backup-oauth-complete`。

旧账号完整备份入口使用原密码下载、解密校验，复制校验通过的归档到官方对象存储，再经恢复预览转换为普通条目。新客户端不会向旧账号快照接口写入。旧对象保留用于兼容。

账号服务器在调试时可通过运行环境 `EIZHU_ACCOUNT_SERVER` 指定；生产构建在编译时通过同名变量注入地址。未配置的默认地址是不可用占位值。官方对象存储部署配置只在独立闭源服务端仓库维护，公开仓库不保存服务端源码或部署秘密。
